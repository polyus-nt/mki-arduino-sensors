# Arduino Sensor

Актуальная прошивка: [arduino-sensor.ino](arduino-sensor.ino).
В проекте один скетч; старые скетчи DS18B20 и их протокол удалены.

Состав: BMP280×3 (температура и давление), VOC×2, DHT11×3,
GP2Y1010AU0F×2, концевики×2. Замки и пылесос обслуживает восьмилампочница.

## Arduino IDE

1. Откройте `arduino-sensor.ino` из папки `arduino-sensor`.
2. Выберите Arduino Uno (проверенная сборка; карта стенда ещё уточняется).
3. Нажмите «Проверить». AustereSerialMaster, SoftwareWire, Adafruit DHT и официальный
   Sensirion Gas Index Algorithm включены в `src/`;
   устанавливать их отдельно не требуется.
4. Для подключения аппаратуры задайте карту в [BoardConfig.h](BoardConfig.h).

Транспорт по умолчанию: MISO=D2, MOSI=D3, CLK=D4, CS=D5, IRQ=D6.
**Пример BMP280 с SCL=D2, SDA=D3/D4/D5 конфликтует с транспортом.**
Он не активирован: сначала нужно переназначить одну из групп.
Все пять транспортных пинов переопределяются вместе через `API_LINK_*`.
Вся распиновка задаётся только в `BoardConfig.h`: транспорт, BMP280, SGP40, DHT11
и концевики. Драйверы получают пины извне и собственной карты не содержат.
Частичная группа Austere/BMP280/SGP40/DHT11 останавливает сборку с ошибкой.
Без карты датчики возвращают NOT_IMPLEMENTED, не фиктивные измерения.

## BMP280

[BMP280.h](BMP280.h) — реальный драйвер с отдельной калибровкой каждого датчика.
[src/BMP280SoftwareBus.h](src/BMP280SoftwareBus.h) — адаптер SoftwareWire:
общий SCL, три независимых SDA, адрес 0x76, 50 кГц, внутренние подтяжки отключены.
Нужны внешние подтяжки и согласованные безопасные уровни питания/сигналов.

Драйвер проверяет ID=0x58, готовность NVM, калибровку; включает normal mode
с oversampling x1 для температуры и давления. Инициализация выполняется по шагам.
Раз в 100 мс считывается пара T/P одним блоком 6 байтов, применяются формулы
компенсации из [документации Bosch](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmp280-ds001.pdf).
При ошибке сохраняется последнее валидное значение с растущим возрастом,
повторная инициализация начинается через секунду. До первого измерения —
SENSOR_UNAVAILABLE.

В кадре: температура — signed i32 в сотых °C; давление — unsigned u32 в **Па**,
оба big-endian, затем valid/fresh и возраст в миллисекундах.
Никаких Serial.println или передачи текстовых float: кадр уходит побайтово через Austere.
Пыль возвращает NOT_IMPLEMENTED до реализации и согласования единиц/форматов.
Концевики включаются только с картой и полярностью.

SoftwareWire 1.6.0 включён с локальной поправкой: тайм-аут 20 мс относится ко
всей I²C-операции, ошибка clock stretching не маскируется успешным чтением.
Это ограниченно синхронный I²C, не полностью неблокирующий транспорт.
Лицензия и изменения: [src/softwarewire/UPSTREAM.md](src/softwarewire/UPSTREAM.md).

## VOC: SGP40 ×2

[SGP40.h](SGP40.h) — отдельный класс модели датчика, два независимых экземпляра.
Команды и время преобразования: [datasheet SGP40](https://sensirion.com/resource/datasheet/sgp40).
[src/SGP40SoftwareBus.h](src/SGP40SoftwareBus.h) — две программные I²C-шины:
адрес 0x59, 50 кГц, без внутренних подтяжек, тайм-аут всей операции 20 мс.
Каждые 1000 мс отправляется measure_raw_signal, через минимум 35 мс после
завершения отправки команды читается
ответ из трёх байтов; ожидание организовано автоматом состояний, без delay.
CRC-8 Sensirion (начальное FF, полином 31) проверяется до обработки raw.
Компенсация пока фиксированная RH=50%, T=25°C, как в предоставленном примере.
Подключение DHT11/BMP280 к компенсации не реализовано без карты соответствия.

Используется [официальный алгоритм Sensirion](https://github.com/Sensirion/arduino-gas-index-algorithm)
с периодом 1 с: C core и две статические структуры состояния, без выделения heap.
Зависимость закреплена commit в [src/sensirion/UPSTREAM.md](src/sensirion/UPSTREAM.md).
`get_voc(0..1)` возвращает **безразмерный VOC Index 1..500, не ppm и не raw**.
В кадре — u32 big-endian, затем flags (1=valid, 3=valid+fresh), u16 ageMs
(насыщение 65534), последний байт данных нулевой.
Начальный ноль алгоритма во время blackout (~45 с) не возвращается как валидный:
до первого Index — SENSOR_UNAVAILABLE. При CRC/I²C-ошибке остаётся предыдущий
валидный Index с растущим возрастом и без fresh; алгоритм перезапускает blackout.
При перерыве между стартами >=2000 мс или задержке чтения >=1000 мс — такой же reset.
Обычный джиттер loop допустим; пропущенные секунды не догоняются burst-вызовами.

Все четыре `API_VOC{0,1}_{SDA,SCL}_PIN` задаются вместе, не пересекаются
между собой, с Austere, BMP280 и концевиками. **SCL=D6 из примера пересекается
IRQ=D6**. По умолчанию VOC-пины отключены (NOT_IMPLEMENTED), не угаданы.
Каждый тип датчика оформлен отдельно: BMP280.h, SGP40.h, DoorSwitch.h.
DHT11.h реализован; GP2Y1010AU0F.h пока безопасная заглушка без GPIO.
Общий round-robin обслуживает один из восьми BMP/VOC/DHT за idle-итерацию.
I²C имеет тайм-аут 20 мс; синхронные ограничения DHT описаны ниже.

## Влажность: DHT11 ×3

[DHT11.h](DHT11.h) — три независимых экземпляра с собственным кэшем и периодом.
[src/DHT11Hardware.h](src/DHT11Hardware.h) использует локальную Adafruit DHT
1.4.6; библиотека и MIT-лицензия включены в `src/dht/`, без внешних зависимостей.
Константа типа переименована DHT_TYPE_11, чтобы не конфликтовать с классом DHT11.
GPIO-тайм-аут обрывает захват сразу, а не после всех остальных импульсов.

В BoardConfig.h нужно задать вместе API_DHT0_PIN/API_DHT1_PIN/API_DHT2_PIN.
Пины 8/9/10 из примера не включены автоматически: они пересекаются с тестовой
картой VOC. Проверяются пересечения с транспортом, BMP, VOC и концевиками.
Без карты — NOT_IMPLEMENTED; до первого успешного чтения — SENSOR_UNAVAILABLE.

Первое чтение — через 2 с после begin; дальнейшие — не раньше 2 с после конца
предыдущей попытки. `delay(2000)` и печати измерений нет. API читает только кэш,
не запускает GPIO. Физическое чтение через `readHumidity(true)` проверяет checksum;
NaN/ошибка/значение вне 0..100% не становится успешным измерением. После ошибки
старое валидное значение сохраняется с fresh=0 и растущим возрастом.

`get_humidity(idx)` (0x24, idx=0..2) передаёт u32 в сотых % RH, big-endian:
55.5% -> 5550 -> `00 00 15 AE`; далее flags, u16 age_ms и нулевой байт.
Это представление протокола, не обещание точности DHT11 в 0.01%.
Температура API по-прежнему поступает от BMP280, не от DHT11.

Чтение DHT **не полностью неблокирующее**: библиотека содержит 1+20 мс стартовых
задержек и временно отключает прерывания при приёме импульсов. Оно выполняется
только в idle-итерации после обслуживания Austere. Arduino здесь сама тактирует
Austere и проверяет уровень IRQ, поэтому обмен на время чтения просто откладывается;
совместимость с реальным шлюзом и запас стека всё равно нужно проверить на стенде.
[Оригинальный исходник DHT](https://github.com/adafruit/DHT-sensor-library/blob/1.4.6/DHT.cpp).

## Структура и проверки

- `src/SensorApi.h` — команды и диапазоны индексов.
- `src/BoardIO.h` — composition BMP280×3/SGP40×2/DoorSwitch×2, карта и кодирование.
- `src/common/HardwareProtocol.h` — бинарный кадр 20 байтов с CRC.
- `src/austere/` — локальная AustereSerialMaster с лицензией upstream.
- `src/main.cpp` — только адаптер PlatformIO; Arduino IDE собирает корневой .ino.

```sh
pio run -e uno
pio run -e uno_bmp_compile_check
pio run -e uno_sensors_compile_check
pio run -e uno_dht_compile_check
```

Вторая конфигурация включает весь BMP-код с конфликтующей картой из примера:
это только проверка компиляции, **не прошивка для стенда**.
Третья конфигурация собирает BMP280×3, SGP40×2 и два концевика с искусственной
непересекающейся картой: также только compile-check, не согласованная проводка.
Карты проверок находятся в `test/compile_only_bmp.h` и
`test/compile_only_sensors.h`; `platformio.ini` подключает только заголовок.
`test/conflicting_sensors.h` проверяет пересечение SCL VOC с IRQ транспорта,
`test/partial_transport.h` — обязательную ошибку неполной транспортной карты.
`test/compile_only_dht.h` добавляет DHT на 13/18/19 ТОЛЬКО для полной сборки,
это не согласованная разводка. `test/conflicting_dht.h` проверяет конфликт с IRQ.
Полная сборка с DHT: статическая RAM Uno 1390/2048 байт, остаток 658 байт нужен
стеку (внутри Adafruit есть локальный массив 320 байт); требуется стендовая проверка.
[Протокол и межрепозиторные проверки](../tjc-commutator/docs/FIRMWARE-IMPLEMENTATION.md).
Старый код восстанавливается из истории Git.
