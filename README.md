# Узел датчиков Arduino

Скетч опрашивает два датчика температуры DS18B20, датчик Холла и три входа
концевых выключателей. Для обмена с контроллером используется `AustereSerialMaster`.

## Зависимости

- Arduino Core;
- библиотека `OneWire`;
- библиотека `AustereSerialMaster`;
- локальные файлы проекта: `DS18B20.h`, `KY-024.h`, `Koltsevik.h`,
  `Led.h` и `LED.ino`.

## Назначение пинов

| Назначение | Пин |
| --- | --- |
| AustereSerial MISO | D2 |
| AustereSerial MOSI | D3 |
| Тактовый сигнал AustereSerial | D4 |
| Chip Select AustereSerial | D5 |
| IRQ AustereSerial | D6 |
| DS18B20 внутри теплоизоляционного блока | A3 |
| DS18B20 снаружи | A4 |
| Концевики | A0, A1, A2 |
| Цифровой выход датчика Холла KY-024 | D12 |

`ACTUATOR_CODE` — сохранённый совместимый однобайтный запрос; он не управляет
светодиодом и не занимает дополнительный пин.

## Команды шины

Узел датчиков принимает однобайтные команды.

| Код | Имя | Действие | Ответ |
| ---: | --- | --- | --- |
| `0x01` | `POLLING_CODE` | Обновляет значения всех датчиков. | `0x03` |
| `0x02` | `ACTUATOR_CODE` | Переключает светодиод. | `0x03` |
| `0x04` | `SEND_CODE` | Передаёт последние собранные измерения. | Полезные данные, затем `0x03` |

`0x03` — это `OK_CODE`.

## Полезные данные `SEND_CODE`

После команды `SEND_CODE` скетч передаёт байты в следующем порядке:

| Индекс | Значение | Тип / диапазон |
| ---: | --- | --- |
| 0 | Датчик Холла | `0` или `1` |
| 1 | Концевик A1 | `0` или `1` |
| 2 | Концевик A2 | `0` или `1` |
| 3 | Концевик A0 | `0` или `1` |
| 4 | Целая часть температуры внутри | Знаковый `int8_t`, переданный как байт |
| 5 | Дробная часть температуры внутри | Нормализованное значение `0..255` |
| 6 | Целая часть температуры снаружи | Знаковый `int8_t`, переданный как байт |
| 7 | Дробная часть температуры снаружи | Нормализованное значение `0..255` |
| 8 | Флаги температур | bit 0/1: inside valid/fresh; bit 2/3: outside valid/fresh |
| 9 | `OK_CODE` | Всегда `0x03` |

Полезные данные отправляются после отдельной команды `POLLING_CODE`, которая
обновляет значения датчиков. Признак `fresh` устанавливается только после
нового успешного чтения scratchpad с корректным CRC; повтор последнего
валидного значения не считается свежим измерением.

### Декодирование температуры

Целая часть на линии является представлением `int8_t` в виде `uint8_t`:

```cpp
int8_t whole = rawWhole < 128 ? rawWhole : rawWhole - 256;
uint8_t hundredths = round(rawFraction * 99.0f / 255.0f);
float temperature = whole + hundredths / 100.0f;
```

Для отрицательных температур целая часть округляется вниз. Например, `-0.25 C`
кодируется как `-1` и `0.75`, а формула выше восстанавливает `-0.25 C`.

## Неблокирующее чтение температуры

Оба DS18B20 работают через `DS18B20.h`. Вызов `readTemperature()` не ожидает
завершения преобразования: пока измерение выполняется, метод возвращает
последнее корректное значение. При 12-битной точности преобразование может
занимать до 750 мс. Сразу после подачи питания внутреннее значение `0.0` может
находиться только в локальном буфере, но в протоколе оно сопровождается
`valid=0, fresh=0` и не должно восприниматься как температура. После первого
CRC-корректного чтения последнее значение остаётся `valid=1`; ошибка CRC или
отсутствие датчика сбрасывают только `fresh`.

В активном пути опроса нет `delay()`. Датчик Холла и концевики считываются сразу.
Концевик считается активным, когда `analogRead()` возвращает значение строго
меньше `50`; в этом случае в протокол передаётся `1`, иначе — `0`.

## Диагностика через USB Serial

USB Serial запускается на скорости 9600 бод и выводит только сообщения старта.
Значения датчиков передаются через `AustereSerialMaster`, а не через `Serial`.
